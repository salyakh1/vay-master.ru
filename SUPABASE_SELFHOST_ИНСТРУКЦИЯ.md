# Пошаговая инструкция: свой Supabase в России (простыми словами)

Инструкция для того, чтобы твой сайт VAY-MASTER работал из России без VPN. Всё по шагам, каждый шаг расписан подробно.

---

## Что мы будем делать (одной фразой)

Купим «компьютер в интернете» (сервер) в России, установим на него программу Supabase, перенесём туда базу данных и в настройках сайта укажем адрес этого сервера. После этого сайт будет ходить за данными в Россию, а не за границу.

---

## Что тебе понадобится

- Банковская карта (или помощь взрослого) — сервер платный, примерно 300–700 ₽ в месяц.
- Email — для регистрации у хостинга и для входа на сервер.
- Твой проект на компьютере (папка vay-master.ru) и папка `supabase` с файлами `.sql`.
- 1–2 часа времени и спокойствие: если что-то пойдёт не так, можно повторить шаг.

---

# ШАГ 1. Выбор и покупка сервера (VPS)

## 1.1. Что такое VPS

VPS — это виртуальный сервер. Как будто тебе выделили отдельный компьютер в дата-центре. На него можно установить программы (в нашем случае — Supabase), и твой сайт будет обращаться к нему по интернету.

## 1.2. Где купить (примеры в России)

Подойдёт любой из этих сайтов (можно один на выбор):

- **Timeweb** — timeweb.com  
- **Selectel** — selectel.ru  
- **REG.RU** — reg.ru  

Дальше в инструкции будем считать, что ты выбрал **Timeweb** (там проще интерфейс). Если выберешь другой — шаги похожи: «Создать сервер» → выбрать ОС Linux → оплатить.

## 1.3. Регистрация на Timeweb

1. Зайди на **timeweb.com**.
2. Нажми **«Регистрация»** (или «Войти» → «Зарегистрироваться»).
3. Введи email, придумай пароль, согласись с правилами, нажми **«Зарегистрироваться»**.
4. Подтверди почту (перейди по ссылке из письма).
5. Войди в личный кабинет (логин = email, пароль тот, что придумал).

## 1.4. Создание сервера (VPS)

1. В личном кабинете найди раздел **«Серверы»** или **«VPS»** (в меню слева или сверху).
2. Нажми **«Создать сервер»** / **«Заказать VPS»**.
3. Выбери:
   - **ОС:** Ubuntu 22.04 (или просто Ubuntu — последняя версия).
   - **Тариф:** минимальный с **2 GB оперативной памяти** (часто называется «Минимальный» или «Старт»). Если есть вариант с 4 GB и он не сильно дороже — можно взять его.
   - **Регион:** Россия (Москва или другой российский город, если есть выбор).
4. Придумай пароль для сервера (его потом будем вводить при входе). **Обязательно сохрани его** в блокноте.
5. Нажми **«Оформить»** / **«Оплатить»**. Спишут деньги (обычно 300–700 ₽ в месяц).
6. Подожди 5–10 минут. В списке серверов появится твой сервер. У него будет:
   - **IP-адрес** (например: 123.45.67.89) — запомни или скопируй.
   - **Логин** (часто `root`).
   - **Пароль** — тот, что ты задал.

Запиши у себя: IP = …, логин = root, пароль = … .

# ШАГ 2. Подключение к серверу

Нам нужно «зайти» на этот сервер с твоего компьютера и вводить команды там. Это делается через программу, которая подключается по SSH.

## 2.1. Если у тебя Windows

1. Открой **PowerShell** (поиск в Windows: «PowerShell» → запустить).
2. Введи команду (подставь свой IP вместо `123.45.67.89`):
   ```bash
   ssh root@123.45.67.89
   ```
3. Спросят: «Trust this host?» — напиши **yes** и нажми Enter.
4. Спросят пароль — введи пароль от сервера (тот, что задавал при создании). При вводе пароль не отображается — это нормально, просто введи и нажми Enter.
5. Если всё верно, в начале строки появится что-то вроде `root@server:~#` — значит, ты внутри сервера.

## 2.2. Если не получается через PowerShell (Windows)

Установи программу **PuTTY** (бесплатная):

1. Скачай с сайта: putty.org (файл putty.exe).
2. Запусти PuTTY.
3. В поле «Host Name» введи IP сервера (например 123.45.67.89). Порт оставь 22.
4. Нажми **Open**. Введи логин `root`, потом пароль. Оказался в консоли сервера — дальше все команды вводишь там.

## 2.3. Если у тебя Mac или Linux

Открой «Терминал» и выполни:
```bash
ssh root@ТВОЙ_IP
```
Подставь свой IP, введи пароль. Дальше все шаги одинаковые — команды вводишь в этой консоли.

# ШАГ 3. Установка Docker на сервер

Docker — это программа, которая умеет «упаковывать» другие программы и запускать их одной командой. Supabase как раз ставится через Docker.

## 3.1. Обновление системы

В консоли сервера (где у тебя `root@...`) введи по очереди, после каждой нажимай Enter и жди окончания:

```bash
apt update
```

```bash
apt upgrade -y
```

Может спросить «Do you want to continue?» — напиши **y** и Enter. Подожди, пока всё обновится.

## 3.2. Установка Docker

Скопируй и вставь в консоль целиком (одной строкой), нажми Enter:

```bash
curl -fsSL https://get.docker.com | sh
```

Подожди 1–2 минуты. В конце должно быть что-то вроде «Docker installed».

Потом включи Docker, чтобы он запускался при перезагрузке:

```bash
systemctl enable docker && systemctl start docker
```

Проверь, что Docker работает:

```bash
docker --version
```

Должна появиться строка с версией (например `Docker version 24.0.7`). Если есть — переходи к шагу 4.

## 3.3. Установка Docker Compose

Docker Compose нужен, чтобы запускать сразу несколько «контейнеров» (база, auth, хранилище и т.д.) одной командой.

```bash
apt install docker-compose-plugin -y
```

Проверка:

```bash
docker compose version
```

Должна показаться версия. Если да — всё готово к следующему шагу.

# ШАГ 4. Установка Supabase на сервер

## 4.1. Создание папки и скачивание Supabase

В консоли сервера:

```bash
cd /opt
```

```bash
git clone --depth 1 https://github.com/supabase/supabase
```

Если напишет «git: command not found», сначала установи git:

```bash
apt install git -y
```

Потом снова выполни `git clone` из этого пункта.

## 4.2. Переход в папку с настройками

```bash
cd /opt/supabase/docker
```

Здесь лежат файлы для запуска Supabase через Docker.

## 4.3. Копирование файла с настройками

Нужно создать свой файл с паролями и ключами (чтобы они не были «дефолтными»). Выполни:

```bash
cp .env.example .env
```

Теперь открой этот файл для редактирования:

```bash
nano .env
```

В открывшемся редакторе найди строки (можно искать стрелками):

- `POSTGRES_PASSWORD=postgres` — замени на свой сложный пароль для базы, например: `POSTGRES_PASSWORD=МойСекретныйПароль123`
- Запомни или запиши этот пароль — он понадобится, если будешь заходить в базу вручную.

Остальное пока можно не менять. Сохрани файл: нажми **Ctrl+O**, Enter, потом **Ctrl+X** (выход).

## 4.4. Запуск Supabase

В той же папке (`/opt/supabase/docker`) выполни:

```bash
docker compose up -d
```

Подожди 5–10 минут. Docker скачает образы и запустит все сервисы. В конце должно быть что-то вроде «done» или список контейнеров.

Проверь, что контейнеры работают:

```bash
docker compose ps
```

Должны быть в статусе «Up» несколько строк (postgres, auth, rest, storage и т.д.).

# ШАГ 5. Узнать URL и ключи Supabase

Сайт должен обращаться к твоему Supabase по адресу и с ключом. Пока Supabase слушает только по HTTP и по IP (без домена). Потом можно будет настроить домен и HTTPS.

## 5.1. Где лежат ключи

Ключи и пароли генерируются при первом запуске и попадают в контейнеры. Их можно посмотреть так.

Выполни на сервере:

```bash
docker compose exec studio cat /usr/local/share/supabase/.env 2>/dev/null || docker compose exec api env | grep -E "ANON_KEY|SERVICE_ROLE"
```

Или проще — зайди в веб-интерфейс Studio (если он включён в твоей сборке). Обычно он доступен по адресу:

`http://ТВОЙ_IP:3000`

Открой в браузере (подставь свой IP):  
**http://123.45.67.89:3000**  
(или тот порт, который указан в docker-compose для studio).

В Studio можно посмотреть **Settings → API**: там будет **Project URL** и **anon public** key.

Если Studio нет или не открывается — ключи можно достать из контейнера `api`:

```bash
docker compose exec api env | grep SUPABASE
```

Ищи строки вроде:
- `SUPABASE_URL=http://...` — это твой URL (только вместо localhost подставь свой IP, например `http://123.45.67.89:8000` если API слушает на порту 8000).
- `SUPABASE_ANON_KEY=eyJ...` — длинная строка, это anon key.

В официальной сборке Supabase в папке `docker` часто в `.env` после первого запуска появляются сгенерированные ключи — можно снова открыть:

```bash
nano /opt/supabase/docker/.env
```

и поискать там `ANON_KEY` и `SERVICE_ROLE_KEY`. **anon** — тот, что нужен для сайта (его можно вставлять во фронт). **service_role** — только для сервера, никому не показывай.

## 5.2. Какой URL использовать в проекте

- Если Supabase в docker слушает на порту **8000** (стандарт для API), то URL для сайта будет:  
  **http://ТВОЙ_IP:8000**  
  Например: `http://123.45.67.89:8000`
- Запиши: **Мой Supabase URL** = `http://ТВОЙ_IP:8000`  
- Запиши: **Мой anon key** = та длинная строка `eyJ...`, которую нашёл выше.

# ШАГ 6. Перенос базы данных (твои таблицы)

Сейчас в твоём Supabase база пустая. Нужно создать таблицы и данные по тем SQL-файлам, что лежат в проекте в папке `supabase`.

## 6.1. В каком порядке выполнять SQL

В папке `supabase` у тебя много файлов. Важно выполнять их **в правильном порядке**: сначала базовый `schema.sql`, потом миграции по очереди (по дате или по зависимостям).

Обычно порядок такой:

1. **schema.sql** — основные таблицы (profiles, posts, products, chats, messages и т.д.)
2. Остальные файлы — по названию/дате: например `fix_rls.sql`, `portfolio_schema.sql`, `orders_schema.sql` и все остальные из папки `supabase`.

Лучше сделать так: на **своём компьютере** (не на сервере) открой папку `vay-master.ru/supabase` и составь один общий файл или список файлов по порядку. Или выполнять по одному, начиная с `schema.sql`.

## 6.2. Как выполнить SQL на сервере

Подключись к базе PostgreSQL внутри Docker. На сервере выполни:

```bash
docker compose exec db psql -U postgres
```

(Если пароль спрашивает — введи тот, что задавал в `POSTGRES_PASSWORD` в `.env`.)

Ты окажешься в консоли базы (`postgres=#`). Здесь можно вставлять SQL.

Самый простой способ — не вставлять всё вручную, а «скормить» файл. Выйди из psql (напиши `\q` и Enter). Потом на сервере нужно скопировать твой `schema.sql` на сервер. С твоего компьютера это делают так (в **новом** окне терминала на твоём ПК, не на сервере):

```bash
scp -r "C:\Users\saleh\Desktop\vay-master.ru\supabase" root@ТВОЙ_IP:/opt/supabase_project/
```

(Подставь свой IP и свой путь к папке vay-master.ru, если он другой. Для Mac/Linux путь будет вида `/Users/.../vay-master.ru/supabase`.)

На сервере потом:

```bash
docker compose exec -T db psql -U postgres < /opt/supabase_project/supabase/schema.sql
```

(Путь `/opt/supabase_project/supabase/` замени на тот, куда ты скопировал папку `supabase`.)

Если копировать не хочешь — открой на своём компьютере файл `supabase/schema.sql`, скопируй весь текст, на сервере зайди в psql (`docker compose exec db psql -U postgres`) и вставь туда содержимое по частям (несколько раз по куску) и нажимай Enter.

После `schema.sql` выполни остальные нужные миграции тем же способом (по одному файлу), чтобы появились все таблицы: портфолио, заказы, баннеры, чаты и т.д.

Если какая-то команда выдаст ошибку (например «table already exists») — можно пропустить этот файл или эту строку и идти дальше.

# ШАГ 7. Настройка проекта на твоём компьютере

Теперь нужно сказать твоему сайту: «ходи не на supabase.co, а на мой сервер».

## 7.1. Открыть файл с настройками

На своём компьютере открой папку проекта **vay-master.ru**. В корне найди файл **`.env.local`**. Если его нет — скопируй `env.example` и переименуй копию в `.env.local`.

Открой `.env.local` в блокноте или в редакторе кода.

## 7.2. Заменить URL и ключ

Найди строки:

- `NEXT_PUBLIC_SUPABASE_URL=...`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY=...`

Замени их на свои значения с сервера:

```env
NEXT_PUBLIC_SUPABASE_URL=http://123.45.67.89:8000
NEXT_PUBLIC_SUPABASE_ANON_KEY=твой_длинный_anon_ключ_eyJ...
```

(Вместо `123.45.67.89` подставь свой IP сервера, вместо `твой_длинный_anon_ключ` — тот ключ, что ты записал в шаге 5.)

Сохрани файл.

## 7.3. Перезапуск сайта

Если у тебя запущен `npm run dev`, останови его (Ctrl+C в терминале) и запусти снова:

```bash
npm run dev
```

Сайт снова откроется на localhost. Но теперь он будет обращаться за данными и входом к твоему Supabase в России.

# ШАГ 8. Проверка, что всё работает

1. Открой в браузере твой сайт: **http://localhost:3000** (или тот порт, что показывает Next.js).
2. Нажми **«Войти»** и введи данные тестового аккаунта (или зарегистрируй нового пользователя).
3. Если вход прошёл и ты попал на главную — значит, Auth и база уже идут на твой сервер.
4. Зайди в разделы: лента, профиль, заказы. Если страницы открываются без ошибок — запросы к базе идут на твой Supabase.

Если при входе или на странице видишь ошибку «Failed to fetch» или «Connection refused»:
- Проверь, что на сервере контейнеры запущены: на сервере выполни `docker compose ps` в папке `/opt/supabase/docker`.
- Проверь, что в `.env.local` верный IP и порт (тот, на котором слушает API, обычно 8000).
- Убедись, что брандмауэр на VPS не блокирует порт 8000 (в панели Timeweb/Selectel часто есть «Сеть» / «Firewall» — порт 8000 и 3000 должны быть открыты для входящих).

# Краткая шпаргалка (что делать по порядку)

1. Купить VPS (Ubuntu), записать IP, логин, пароль.  
2. Подключиться по SSH: `ssh root@IP`.  
3. Установить Docker и Docker Compose (команды из шага 3).  
4. Установить Supabase: клонировать репозиторий в `/opt/supabase`, в `docker` сделать `cp .env.example .env`, поправить пароль БД, выполнить `docker compose up -d`.  
5. Узнать URL (http://IP:8000) и anon key (через Studio или `docker compose exec api env`).  
6. Перенести базу: выполнить `schema.sql` и остальные миграции из папки `supabase` в PostgreSQL на сервере.  
7. В проекте в `.env.local` прописать новый URL и anon key, перезапустить `npm run dev`.  
8. Проверить вход и страницы на localhost.
