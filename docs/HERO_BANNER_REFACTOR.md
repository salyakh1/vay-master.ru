### Архитектурные проблемы

1. **Нет разделения 60/40** — текст и изображение смешаны в одном слое, нет чёткой контентной зоны слева и визуальной справа.
2. **Full-bleed background** — картинка на весь баннер, текст поверх; нет отдельного контейнера под изображение и глубины.
3. **Слабая типографическая иерархия** — нет уровня H1 (22–24px, 700), нет badge, подзаголовок и малый текст не выделены.
4. **Нет верхнего левого label** — типа «Акция» / «Рекомендуем».
5. **Нет кнопки меню (⋮)** в правом верхнем углу.
6. **Высота и скругление** — 180px / 280px и общий вид не совпадают с целевым hero (200px, 22px radius, 16px padding).
7. **Контраст** — текст поверх изображения может теряться на светлых картинках; нет гарантированного контраста за счёт отдельной левой зоны с фоном.
8. **Нет изолированного визуала** — изображение не вынесено в правую зону с выходом за край (depth).

## ЭТАП 2–4 — ЧТО ИЗМЕНЕНО АРХИТЕКТУРНО

### Геометрия

- **Height:** 200px (mobile), фиксированно.
- **Border-radius:** 22px.
- **Padding:** 16px.
- **Overflow:** hidden у контейнера.
- **Position:** relative, width 100%.

### Layout

- **Flex row:** левая зона 60%, правая 40%.
- **Левая зона (контент):**
  - Верхний левый label (Акция / Рекомендуем / Мастер / Товар по типу баннера).
  - H1: 22–24px (clamp), font-weight 700, `text-graphite-secondary`.
  - Badge: inline-block, padding 6px 12px, border-radius 14px, `bg-brand-accent text-white` (данные: `badge_text` или обрезка `description`).
  - Подзаголовок: 14px, `text-text-secondary`, при наличии отдельного описания.
  - Gap между элементами 8–12px.
- **Правая зона (визуал):**
  - Изображение в отдельном контейнере, `height: 100%`, `object-fit: cover`.
  - Выход за правую границу (`right: -16px`, расширенная ширина) для depth-эффекта.

### Механика (как у vseinstrumenti)

- Поддержка массива баннеров — без изменений (уже была).
- Swipe — без изменений (touch handlers сохранены).
- Pagination dots — absolute, bottom-center, отступ снизу 16px, z-index 10.
- Автосмена — без изменений (опционально, через `autoplay` и `duration`).
- Lazy load — первый слайд `loading="eager"`, остальные `loading="lazy"`.

### UX-детали

- Верхний левый label по типу баннера (Акция / Рекомендуем / Мастер / Товар).
- Кнопка ⋮ (FiMoreVertical) в правом верхнем углу, z-index 10, ведёт на переход баннера.
- Контроль z-index: контент z-[2], визуал z-[1], dots и кнопка z-[10].
- Контраст: текст только в левой зоне на фоне страницы/карточки (без наложения на картинку), цвета из дизайн-токенов.

### Что не трогали

- API `/api/banners`, загрузка по `page` и `initialBanners` — без изменений.
- Трекинг просмотров и кликов (`/api/banners/[id]/view`, `/api/banners/[id]/click`) — без изменений.
- Логика переходов (external_url, master, product, category, order) — без изменений.
- Админка баннеров — без изменений; используются существующие поля `title`, `description`, `image_url`, `type`, `show_badge`, `badge_text`, `duration` и т.д.

## ЭТАП 6 — ПОЧЕМУ ЭТО УЛУЧШИТ CTR

1. **Читаемость** — текст в левой зоне с гарантированным контрастом, без зависимости от яркости картинки.
2. **Иерархия** — явный H1 + badge + подзаголовок ведут взгляд и выделяют оффер.
3. **Узнаваемая структура** — 60/40 и layout как у vseinstrumenti снижают когнитивную нагрузку и повышают доверие.
4. **Depth-эффект** — выход изображения за край добавляет объём и привлекает внимание к правой части.
5. **Label и CTA** — верхний label («Акция»/«Рекомендуем») и кнопка ⋮ задают контекст и явную точку клика.
6. **Единая высота и скругление** — 200px и 22px дают стабильный, «мобильный» hero и уменьшают визуальный шум.

## БАГ: Текст первого баннера накладывался на второй слайд

### ЭТАП 1 — Причина

Проверка по чек-листу:

| № | Вопрос | Было | Нужно |
|---|--------|------|--------|
| 1 | Flex для обёртки слайдов? | Да | ✓ |
| 2 | min-width: 100% у каждого слайда? | Нет — `width: (100/N)%` | Добавлен `minWidth: '100%'` + width в % от контейнера |
| 3 | overflow: hidden у родителя? | Да | ✓ |
| 4 | position: relative у wrapper? | Да | ✓ |
| 5 | translateX? | **Ошибка:** `translateX(-index * 100%)` | Должно быть `translateX(-index * (100/N)%)` |
| 6 | width: auto у слайдов? | Нет | ✓ |
| 7 | Абсолютные элементы без ограничения ширины? | Текстовая зона: `overflow-visible` | Исправлено на `overflow-hidden` |

**Точная причина наложения:**

1. **Неправильный translateX.** В CSS процент в `transform: translateX(-100%)` считается от **размера самого элемента** (SlidesContainer). Контейнер имел `width: N*100%` (например 200% для двух слайдов). То есть один «шаг» 100% = сдвиг на **целую ширину контейнера** (два слайда), а не на один слайд. В результате сдвиг не совпадал с границами слайдов, и видимая область показывала «полтора» слайда — текст первого наезжал на второй.
2. **Текстовая зона с overflow-visible.** Левый блок с заголовком/описанием имел `overflow-visible`, поэтому текст мог выходить за границы слайда и отображаться поверх соседнего.

### ЭТАП 2 — Что было сломано

- **Формула сдвига:** использовалось `translateX(-${index * 100}%)` вместо `translateX(-${index * (100 / banners.length)}%)`. На один шаг нужно сдвигать на долю контейнера, равную одному слайду: `(100/N)%`.
- **Контейнер слайдов:** у HeroWrapper был внутренний `padding: 16px`; высота задавалась, но видимая ширина для расчёта процентов — с учётом padding. Padding перенесён внутрь каждого слайда (padding: 16px у кнопки-слайда), чтобы 100% ширины wrapper = ровно одна видимая «полоса».
- **Границы контента:** текстовая зона с `overflow-visible` позволяла контенту выходить за пределы слайда; блок изображения справа выходил за пределы слайда (`right: -PADDING`, `width: calc(100% + 20px)`). Слайд не обрезал содержимое по границе.

### ЭТАП 3 — Финальная архитектура карусели

```
HeroWrapper (ref={containerRef})
  width: 96% (или 100%), height: MOBILE_HEIGHT
  overflow: hidden, position: relative, box-border
  └── SlidesContainer
      display: flex, h-full
      transition: transform 0.4s ease-out
      width: (banners.length * 100)%
      transform: translateX(-(index * (100/N))%)
      ├── Slide (button)
      │   minWidth: 100%, width: (100/N)%
      │   flex-shrink: 0, overflow: hidden, box-sizing: border-box
      │   padding: 16px, borderRadius: 22px
      │   ├── Text container (65%, overflow-hidden, z-[2])
      │   └── Image container (35%, overflow-hidden, z-[1])
      ├── Slide …
      └── Slide …
  + Pagination dots (absolute bottom-center, z-10)
```

Обязательные параметры соблюдены:

- **HeroWrapper:** `width` (96%), `overflow: hidden`, `position: relative`.
- **SlidesContainer:** `display: flex`, `width: N*100%`, `transition: transform 0.4s ease`, `transform: translateX(-index * (100/N)%)`.
- **Slide:** `minWidth: 100%`, `width: (100/N)%`, `flex-shrink: 0`, `box-sizing: border-box`, `padding: 16`, `borderRadius: 22`, `overflow: hidden`.

Текст внутри слайда — в блоке с `overflow-hidden`; блок изображения ограничен слайдом и расширяется только в пределах слайда (`right: -16`, `width: calc(100% + 16px)`), обрезка по границе слайда.

### Почему слайды теперь изолированы

1. **Сдвиг на ровно один слайд:** `translateX(-index * (100/N)%)` сдвигает контейнер ровно на `index` слайдов. Видимая область (HeroWrapper) всегда совпадает с границами одного слайда — нет «полуслайдов» и наложения.
2. **Каждый слайд ровно (100/N)% ширины контейнера:** при `minWidth: 100%` и `width: (100/N)%` один слайд занимает ровно 1/N ширины SlidesContainer, то есть ровно 100% ширины видимой области. Соседние слайды не заезжают в видимую зону при правильном translateX.
3. **overflow: hidden на слайде и на тексте:** контент (текст и картинка) не выходит за границы кнопки-слайда; текст дополнительно ограничен левым блоком с `overflow-hidden`. Визуал одного баннера не может попасть на соседний слайд.
4. **Padding и скругление внутри слайда:** отступы и скругление заданы у слайда, контент не вылезает за его границы, HeroWrapper не нужен padding для «рамки» — только обрезка по ширине/высоте.
