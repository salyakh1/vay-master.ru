# Инструкция по созданию системного пользователя "Администрация VayMaster"

## Проблема
Таблица `profiles` имеет внешний ключ на `auth.users`, поэтому нельзя просто создать запись в `profiles` без соответствующего пользователя в `auth.users`.

## Решение

### Вариант 1: Использовать существующего администратора (РЕКОМЕНДУЕТСЯ)
Система автоматически использует первого активного администратора для отправки сообщений, если `ADMIN_SYSTEM_USER_ID` не указан.

**Преимущества:**
- Не нужно создавать дополнительного пользователя
- Сообщения будут отправляться от имени реального администратора
- Работает сразу без дополнительных настроек

### Вариант 2: Создать отдельного системного пользователя

1. **Создайте пользователя в Supabase Auth:**
   - Перейдите в Supabase Dashboard → Authentication → Users
   - Нажмите "Add user" → "Create new user"
   - Email: `admin@vaymaster.ru`
   - Password: (сгенерируйте надежный пароль, он не будет использоваться)
   - Скопируйте UUID созданного пользователя

2. **Создайте профиль:**
   - Выполните SQL в Supabase SQL Editor:
   ```sql
   INSERT INTO public.profiles (
     id,
     email,
     full_name,
     role,
     created_at
   ) VALUES (
     'ВАШ_UUID_ЗДЕСЬ',  -- Вставьте UUID из шага 1
     'admin@vaymaster.ru',
     'Администрация VayMaster',
     'client',
     NOW()
   ) ON CONFLICT (id) DO UPDATE SET
     full_name = 'Администрация VayMaster',
     email = 'admin@vaymaster.ru';
   ```

3. **Настройте переменную окружения (опционально):**
   - Добавьте в `.env.local`:
   ```
   ADMIN_SYSTEM_USER_ID=ваш-uuid-здесь
   ```

## Текущая реализация
По умолчанию система использует первого активного администратора, если `ADMIN_SYSTEM_USER_ID` не указан. Это самый простой вариант, который работает сразу.
